# ❄️ SOLID Fridge Architecture

Реализация системы управления "умным холодильником", демонстрирующая применение принципов **SOLID**, **OOP** и паттернов проектирования на практике.

Проект написан в рамках выполнения тестового задания (Quest: Fridge) для демонстрации навыков построения гибкой и расширяемой архитектуры на Java.

---

## 🛠 Технологический стек
- **Java 21** (использование Records, современный синтаксис)
- **Maven** (сборка проекта)
- **JUnit 5** (тестирование)

## 💡 Архитектурные решения
Проект спроектирован так, чтобы добавление новых типов хранилищ или еды не требовало изменения существующего кода (Open-Closed Principle).

### Примененные паттерны:
- **Factory Method (`ShelfFactory`)**: Изолирует логику создания сложных объектов полок, позволяя легко внедрять новые типы хранилищ.
- **Dependency Injection**: Класс `Fridge` не зависит от конкретных реализаций полок, работая через абстракцию `ShelfInterface`. Это позволяет "собирать" холодильник любой конфигурации.
- **Interface Segregation**: Логика сроков годности вынесена в отдельный интерфейс `Expirable`, не перегружая основные сущности.
- **DTO / Records**: Использование `FridgerInfo` (Java Record) для неизменяемой передачи мета-данных устройства.

## 🏗 Структура проекта

| Компонент | Описание |
|---|---|
| **Fridge** | Агрегатор, управляющий состоянием устройства. Соблюдает Single Responsibility Principle (SRP), делегируя хранение полкам. |
| **ShelfInterface** | Контракт для взаимодействия с любыми типами хранилищ. |
| **FridgerInfo** | Immutable-объект (Record) для хранения паспортных данных устройства. |
| **Enums** | `PowerStatus`, `DoorStatus` — типобезопасное управление состоянием. |
